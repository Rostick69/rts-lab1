## Функциональные возможности

- **Классификация задач** по жёсткости временных ограничений: жёсткое / твёрдое / мягкое
- **Классификация системы**: жёсткого реального времени (есть хотя бы одна жёсткая задача) или мягкого
- **Тип дедлайна** каждой задачи: неявный, ограниченный, произвольный
- **Запас времени** `L = D − C` и признак выполнимости дедлайна (`L ≥ 0`)
- **Критическая задача**: жёсткая задача с наименьшим запасом
- **Требуемое время реакции** `R_треб = min(D)` по жёстким задачам (при их отсутствии — по всем)
- **Коэффициент загрузки** `U = Σ(Cᵢ / Tᵢ)` и проверка необходимого условия `U ≤ 1`
- **Архитектурный класс**: однопроцессорная / многопроцессорная / распределённая
- **Вывод** итоговой таблицы и текстового заключения в консоль
- **Исходные данные** читаются из JSON-файла, в коде нет «магических чисел»
- **Проверка данных** при загрузке: неизвестный класс жёсткости или нулевые C, D, T дают понятную ошибку

## Краткие теоретические сведения

**Система реального времени (СРВ)** — система, корректность работы которой зависит не только от результата вычислений, но и от времени, за которое этот результат получен.

### Классы задач по жёсткости

| Класс | Последствия пропуска дедлайна | Пример из варианта |
|-------|-------------------------------|--------------------|
| Жёсткое | Катастрофа, недопустимо | Экстренное торможение |
| Твёрдое | Результат теряет ценность, но вреда нет | Контроль давления в шинах |
| Мягкое | Снижается качество работы | Мультимедиа |

### Типы дедлайнов

| Тип | Условие | Смысл |
|-----|---------|-------|
| Неявный | `D = T` | Задача должна завершиться до следующего запуска |
| Ограниченный | `D < T` | Дедлайн раньше конца периода |
| Произвольный | `D > T` | Экземпляры задачи могут перекрываться |

### Расчётные формулы

| Величина | Формула | Что показывает |
|----------|---------|----------------|
| Запас | `L = D − C` | Сколько времени остаётся до дедлайна |
| Требуемое время реакции | `R_треб = min(D)` | Как быстро система должна реагировать |
| Коэффициент загрузки | `U = Σ(Cᵢ / Tᵢ)` | Доля времени процессора, занятая задачами |

> `U ≤ 1` — **необходимое**, но не достаточное условие планируемости: при `U > 1` набор задач точно не выполним на одном процессоре.

## Входные данные

Данные варианта лежат в `data/variant2.json`. Все времена в миллисекундах.

```json
{
    "title": "бортовая система автомобиля",
    "system": {
        "n_cpu": 1,
        "has_network": false
    },
    "tasks": [
        {"name": "Экстренное торможение", "hardness": "жёсткое", "C": 2, "D": 5, "T": 10},
        {"name": "Управление двигателем", "hardness": "жёсткое", "C": 3, "D": 10, "T": 10},
        {"name": "Контроль давления в шинах", "hardness": "твёрдое", "C": 5, "D": 500, "T": 1000},
        {"name": "Мультимедиа", "hardness": "мягкое", "C": 15, "D": 100, "T": 50}
    ]
}
```

| Поле | Описание |
|------|----------|
| `title` | Название системы (выводится в заголовке) |
| `system.n_cpu` | Число процессоров |
| `system.has_network` | Есть ли сеть между узлами |
| `name` | Имя задачи |
| `hardness` | Класс жёсткости: `жёсткое` / `твёрдое` / `мягкое` |
| `C` | Время выполнения, мс |
| `D` | Относительный дедлайн, мс |
| `T` | Период, мс |

Значения подобраны так, чтобы в наборе встретились все три типа дедлайна.

## Архитектура проекта

```
rts-lab1/
├── src/                          # Исходный код
│   ├── models.py                 # Модель задачи Task (@dataclass) и чтение JSON
│   ├── calculations.py           # Все расчёты и классификация
│   ├── output.py                 # Вывод таблицы и заключения
│   └── main.py                   # Точка входа
├── data/                         # Входные данные
│   ├── variant2.json             # Вариант 2: бортовая система автомобиля
│   └── example_methodichka.json  # Контрольный пример из задания
├── docs/                         # Отчёт по работе
├── rts-lab1.sln                  # Решение Visual Studio
└── README.md
```

Модули зависят друг от друга по цепочке:

```
main.py ──► output.py ──► calculations.py ──► models.py ◄── data/*.json
```

### Функции расчёта (`calculations.py`)

| Функция | Что делает |
|---------|------------|
| `slack(task)` | Запас `L = D − C` |
| `is_feasible(task)` | Выполним ли дедлайн (`L ≥ 0`) |
| `deadline_type(task)` | Тип дедлайна по соотношению D и T |
| `classify_system(tasks)` | Класс системы: жёсткого / мягкого РВ |
| `critical_task(tasks)` | Жёсткая задача с наименьшим запасом |
| `required_reaction_time(tasks)` | `R_треб = min(D)` |
| `utilization(tasks)` | Коэффициент загрузки `U` |
| `classify_architecture(n_cpu, has_network)` | Архитектурный класс системы |

## Сборка и запуск

### Требования

- Python 3.10 или выше
- Сторонние библиотеки не нужны, используется только стандартная библиотека

### Через Visual Studio

1. Клонировать репозиторий: **Git → Clone Repository...**
2. Открыть `rts-lab1.sln`
3. В Solution Explorer: правой кнопкой по `src/main.py` → **Set as Startup File**
4. Запустить (**F5**)

Чтобы запустить программу с другим файлом данных, укажите путь в **Properties → Debug → Script Arguments**, например `data/example_methodichka.json`.

### Через командную строку

```bash
git clone <ссылка на репозиторий>
cd rts-lab1

python src/main.py                                  # вариант 2
python src/main.py data/example_methodichka.json    # контрольный пример из задания
```
